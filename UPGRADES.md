# Upgrades

## 0.33.1

No text form, feature, archived layout or valid-value change, and one narrow
trait-implementation change that can break source compatibility for a custom deserializer, recorded here: `ArchivedDecimal`'s `rkyv::Deserialize<Decimal, D>`
impl was derived and generic over any `D: rancor::Fallible + ?Sized`; it is now written by hand and also
requires `D::Error: rancor::Source`. `rancor::Error`, `rancor::Failure` and `rancor::BoxedError` satisfy it (tests/decimal_archive.rs deserializes a `Decimal` through each); a hand-written
deserializer whose error is not a `Source` no longer type-checks against `Decimal`.

- Under the `rkyv` feature an archived `Decimal` is now read back through
  `Decimal::try_from`: a non-finite float in an archive is refused when the archive is read into a
  native value, directly or nested in any derived `Deserialize`, and a negative zero reads as zero.
  Before, the derived `Deserialize` copied the float unchecked, so `rkyv::from_bytes` admitted NaN
  and infinities. Valid archives read back as before and the bytes of every valid value are
  unchanged (tests/decimal_archive.rs compares them with a raw `f64` archive).
- Boundary kept: the borrowed `ArchivedDecimal` (reading the archived float without deserializing)
  is still only structurally validated.
- A consumer that read an archive holding a non-finite decimal now gets a `rancor` error where it
  got a value; no valid archive changes.

To deploy: repin datom-codec to this release; nothing else changes.

## 0.33.0

Breaking.

- protos 0.33.0: a bare unbalanced `«` inside a guillemet string, or a
  literal `\«`, now reads differently. A consumer holding datom text with
  either form re-reads it and updates the expectation.

To deploy: repin datom-codec (and protos to the same revision it pins,
3c7ade3), run the consumer's tests, and update any expected text that holds
an unbalanced `«` or a literal `\«`.

## 0.32.0

Breaking.

- protos 0.32.0: `textualize` of a projected datom writes the vertical
  canonical print, and a projected tree carries that print's extents (protos
  assigns them; this crate no longer measures a one-line layout). A consumer
  asserting a one-line reply of a nested datom updates the expectation or calls
  `protos::Compactable::compact`.
- The helper kinds are renamed to the kinds `datom-codec-kinds.ethos` names
  them: `Pathing` is `Branchable`, `Budgeting` is `Budgeted`, `Positioning` is
  `Positional`. A consumer importing one of them by name renames the import;
  code generated by the derives needs nothing, since the derive emits the new
  names.

To deploy: repin datom-codec (and protos to the same revision it pins), rename
any import above, run the consumer's tests, and update or compact any one-line
expected text.
